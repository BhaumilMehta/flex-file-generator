# Flex File Generator

A lightweight WordPress developer utility plugin that automatically generates matching PHP template parts and CSS stub files inside the active theme whenever an ACF Flexible Content layout is created or updated.

No admin pages. No build tools. No bloat. Pure WordPress + PHP.

---

## Requirements

| Requirement | Version |
|---|---|
| WordPress | 5.8 or higher |
| PHP | 7.4 or higher |
| Advanced Custom Fields (ACF) | 5.x / 6.x (Free or Pro) |

---

## Installation

1. Copy `flex-file-generator.php` into your plugins directory:
   ```
   wp-content/plugins/flex-file-generator/flex-file-generator.php
   ```
2. Go to **WordPress Admin → Plugins** and activate **Flex File Generator**.
3. That's it — no configuration required.

---

## How It Works

The plugin hooks into ACF's `acf/update_field_group` action. Every time you save a field group in the ACF backend, the plugin:

1. Finds every **Flexible Content** field inside that group.
2. Loops through all its **layouts**.
3. Sanitises each layout name (lowercase, underscores).
4. Creates the following two files in your active theme **if they do not already exist**:

| File | Location |
|---|---|
| PHP template part | `{theme}/template-parts/flexible/flex-{layout_slug}.php` |
| CSS stub | `{theme}/assets/css/{layout_slug}.css` |

5. If the required folders (`template-parts/flexible/` or `assets/css/`) don't exist, they are created automatically.
6. All generated files are set to permission `0664` so they are immediately editable in local development environments.

> **Files are never overwritten.** If a file already exists it is skipped, keeping your work safe.

```
your-active-theme/
├── template-parts/
│   └── flexible/
│       └── flex-blog_posts_grid_section.php
└── assets/
    └── css/
        └── blog_posts_grid_section.css
```

### PHP Template Boilerplate

```php
<?php
/**
 * Flexible Layout: blog_posts_grid_section
 *
 * Called via get_template_part() or directly inside a flexible content loop.
 * Available variable: $layout (array) — the current ACF layout row.
 *
 * @package YourTheme
 */
?>

    <div class="container">

    </div>
</section>
```

```css
}

```

## Automatic CSS Enqueuing

The plugin also handles front-end CSS enqueuing automatically. On every singular post or page, it reads the `page_builder` ACF flexible content meta value and enqueues only the CSS files that exist on disk — one per layout, per page.

This means your theme's flexible content loop works out of the box:

```php
if ( have_rows( 'page_builder' ) ) :
    while ( have_rows( 'page_builder' ) ) : the_row();
        $layout = get_row_layout(); // e.g. "blog_posts_grid_section"
        get_template_part( 'template-parts/flexible/flex', $layout );
    endwhile;
endif;
```

### Enqueue behaviour

| Detail | Behaviour |
|---|---|
| Hook | `wp_enqueue_scripts` |
| Runs on | Singular posts and pages only |
| File check | `file_exists()` — no HTTP request |
| Handle format | `ffg-{layout-slug}` (hyphens, WP convention) |
| Version | `filemtime()` — auto cache-busts when file changes |
| Theme path | Dynamic via `get_stylesheet_directory()` — works with any theme name |

## Plugin Structure

```
flex-file-generator/
└── flex-file-generator.php   (single file — ~275 lines)
```

The entire plugin lives in one file. There are no dependencies, no Composer packages, no npm, no build step.

### Internal sections

| Section | Responsibility |
|---|---|
| 1. Bootstrap | Checks ACF is active before registering any hooks |
| 2. Main Handler | Fires on `acf/update_field_group`, retrieves fields |
| 3. Field Processor | Finds Flexible Content fields, sanitises layout names |
| 4. File Generators | Creates PHP and CSS files with `file_exists()` guard |
| 5. File Content | Boilerplate strings for PHP template and CSS stub |
| 6. CSS Enqueue | Auto-enqueues per-layout CSS on the front end |
| 7. Utility | `ffg_theme_path()` helper for dynamic theme paths |

## Function Reference

All functions are prefixed `ffg_` to avoid conflicts.

| Function | Description |
|---|---|
| `ffg_init()` | Registers ACF hook after plugins are loaded |
| `ffg_handle_field_group_save()` | Entry point when a field group is saved |
| `ffg_process_flex_field()` | Loops layouts inside a Flexible Content field |
| `ffg_maybe_create_php_template()` | Creates the PHP template part if missing |
| `ffg_maybe_create_css_stub()` | Creates the CSS file if missing |
| `ffg_php_template_content()` | Returns PHP boilerplate string |
| `ffg_css_stub_content()` | Returns CSS boilerplate string |
| `ffg_enqueue_flex_styles()` | Enqueues per-layout CSS on front end |
| `ffg_theme_path()` | Resolves absolute path inside active theme |

## Local Development Notes

Files are created with permission `0664` immediately after writing. This resolves the common issue on local environments (Local by Flywheel, MAMP, Laragon, Docker) where files generated by the PHP/web-server process are not editable by your user account.

If you still cannot edit a generated file, run this from your theme root:

```bash
chmod -R 664 assets/css/
chmod -R 664 template-parts/flexible/
```

## FAQ

**Will it overwrite my existing template or CSS files?**
No. The plugin checks `file_exists()` before writing. Existing files are always skipped.

**What happens if ACF is deactivated?**
The plugin checks for ACF on `plugins_loaded`. If ACF is not active, no hooks are registered and the plugin does nothing — no errors, no impact.

**Does it work with ACF Free and ACF Pro?**
Yes, both. It only uses `acf_get_fields()` and `acf/update_field_group`, which are available in both versions.

**Does it work with child themes?**
Yes. All paths use `get_stylesheet_directory()` which always resolves to the currently active theme, whether that is a parent or child theme.

**Can I use a different ACF field key than `page_builder` for enqueuing?**
The enqueue function currently reads the `page_builder` meta key. If your field key differs, find this line in `ffg_enqueue_flex_styles()` and update it:
```php
$flex_modules = get_post_meta( get_the_ID(), 'page_builder', true );
```
